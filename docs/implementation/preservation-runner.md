# Preservation runner implementation status

Refs [#113](https://github.com/BinaryDevil/find-free-parking/issues/113), [approved design](../plans/schema91-preservation-design.md).

This branch is an **incomplete implementation**. The new resolver, adoption preflight and guarded command module are not wired into the operator CLI. Preservation release orchestration and protected-reference delivery are implemented, but CLI integration and complete release proof are still pending; this draft is not ready for operator use. Existing `db:migrate`, baseline marking and code-only release behavior remain unchanged. Only newly created local disposable targets have been bootstrapped, adopted and migrated; shared and production readiness is not established.

Implemented public boundaries:

- `loadMigrationManifest` validates the fixed two-lineage manifest, paths, complete directory coverage and SQL hashes. `resolveMigrationLineage` checks exact ordered history and explicit adoption; it never records excluded legacy operations. The real manifest pins the reviewed foundation from #114 and CI seals both SQL directories and manifest prefixes.
- `verifyAdoptionReference` binds a reviewed baseline-replay reference to the unchanged baseline hash, normalized schema hash, exact pg_dump 17 version/options and explicit strict/application projection. Application projection excludes only the existing documented cloud_admin default ACL blocks. Owners, application ACLs, functions, defaults and other schema objects remain compared.
- `executeMigration` prepares the command boundary with endpoint/role/database-owner checks, rejection of URI query overrides, the same node-pg-migrate advisory lock, explicit baseline bootstrap and transactional adoption using a fresh exported snapshot. The existing CLI has not yet been replaced. A focused actual local database proof covers bootstrap, exact comparison, protected metadata, adoption, lock rejection, selected replay and preservation; final CLI/release proof remains pending.
- `adoptPreservation` requires a snapshot reference, baseline-only history and a fresh read-only target capture matching that reference; it rechecks history before the metadata write. The future command must hold the shared migration advisory lock and execute this operation inside its transaction. The helper alone does not create those protections and must not be called as an operator workflow.

Before an adoption workflow is usable, an operator must replay the exact sealed baseline in an isolated database, capture the private schema-only reference using the stated same-version/options, and obtain review of its normalized fingerprint and provenance. A supplied hash or `provenance` string alone does not prove baseline replay. Production authorization must pin that reviewed metadata hash and reference the review. The target schema must be freshly captured, excluding only migration_meta. Do not retain raw schema captures or connection details in routine logs.

Remaining merge gates: integrate the existing #118 connection guard, wire the operator CLI and finish the actual CLI/release proof without changing committed `[]`; test command/release fail-before-write paths and actual isolated database transactions, locking, adoption and replays; independent Standards/Spec review and final CI. Shared dev and production remain untouched.
